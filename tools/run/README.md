# Offline pipeline runner

Eleven stages walk canonical STAGES order regardless of YAML key order: intake, clarify, contract, prd, us, wireframe, prototype, design, tdd, uiux, handoff. Wireframe/prototype default on with PO gates and independent review; design/uiux stay off. New stages produce one literal Markdown/HTML file each and need no design adapter. Upgrade from 2.0.2 preserves intake–us gate/decision bytes; tdd/handoff definitions change with their new context, so old gates become stale. DS tokens are supplied only through an existing token path added by PO to prototype context.

Run from the project root with Node 18 or later. Runtime imports use only Node built-ins and local modules; installation and network access are unnecessary.

For distribution, commit the kit changes and run `node tools/release/pack.mjs --out /path/to/releases` from a Git checkout. It writes `spec-driven-kit-<version>-<shortsha>.tar.gz` and `SHA256SUMS`, refuses tracked changes with exit 3, and warns about missing release docs. Extract the archive into an empty directory and run its `tools/run/init.mjs` for a fresh project or with `--upgrade [--dry-run]` for an existing one; Git is not required for these installs. `kit-release.json` supplies the release commit, while `tools/package.json` remains the version source. Runtime fixture inputs are included because lint and evals import them.

```sh
node tools/run/init.mjs --project /path/to/empty-project --name "My project" --lang en
node tools/run/doctor.mjs --project /path/to/empty-project
node tools/run/run.mjs --project /path/to/empty-project --head fresh-source --build not-built
node --test tools/run/test/
node fixtures/runner/manual-transcript.mjs
```

Init copies the shared kit-content inventory (excluding eval results), preserves shipped stage/role defaults, creates all configured definitions, a graph with `complete: false`, an unpublished baseline placeholder, PO source and tech-context templates, and an empty spec folder. Replace the sample source with confirmed PO input and supply real approvers/immutable baseline before G5 or decision import. Outside Git, supply `--head`; always supply `--build`.

Default agents are manual. Writers support `codex|claude|manual`; reviewers support `codex|claude|grok|manual`. Select roles separately with `--writer codex --reviewer grok`, or both with `--agent codex|claude|manual`; `--agent "<command>"` selects a project-provided stdin/stdout command for both roles. Grok is reviewer-only: `--writer grok` and `--agent grok` are refused. Init refuses a nonempty target; `--force` copies missing files only and preserves all existing bytes, including config, input, spec and review. On an existing project, `--writer`, `--reviewer` or `--agent` values equal to the existing config continue; a differing value exits 3 with no writes. Symlinked targets/entries are refused.

Run an upgrade from the **new kit checkout**, selecting the existing project:

```sh
node tools/run/init.mjs --project /path/to/existing-project --upgrade --dry-run
node tools/run/init.mjs --project /path/to/existing-project --upgrade
node tools/run/doctor.mjs --project /path/to/existing-project
```

Upgrade plans every replacement, removal, kept obsolete file, config key and new definition version before writing. It replaces shipped kit files byte-for-byte, excluding `.git`, `node_modules` and `evals/results`; unchanged obsolete files recorded by the installing kit are removed, while modified or unknown obsolete files stay and are listed. Input, spec, UI, tests and run records (including approvals, gates, decisions, logs, counters and prior definition versions) are preserved. Changed compiled stage definitions get the next unused numeric version and config selects that version; approvals keep their original binding, so the runner applies its existing stale/scope rules. Definition locations must remain under `review/`. Symlinks are refused. Dry-run writes nothing; the same-kit repeat says `already current` and writes nothing.

Fresh init and upgrade write `kit.lock.json`: available kit commit, kit version, installed and shipped file SHA-256 inventories, their consistency checksum, installing config defaults, init-owned selections, and `configDigest`, the SHA-256 of the kit-owned part of `config/pipeline.yaml` (owner selections such as approvers, agents, roles and stage enabled flags are excluded). Legacy locks without `configDigest` compare whole config bytes until an upgrade rewrites them. Init name, language, writer and reviewer (including `--agent` choices and manual defaults) always remain project-owned, even when equal to the installing default. When a selected value differs from the new default, the plan names the key, kept value and new default. Other unchanged default keys receive new defaults; a key changed differently by both project and kit stops with exit 3 naming the key, without writes. Config values and bindings are edited in existing scalar lines, preserving comments, ordering, indentation and untouched bytes; scalar sequence values can be replaced with comments retained; new keys append in block style within their parent mapping. Unsupported edits (including flow-mapping children, block scalars, nested sequence replacement or key deletion) refuse with exit 3 naming the key and the manual edit. Lint and runner share the bounded config parser, which also accepts legacy JSON. For a JSON config written by a prior upgrade, an exact match to its recorded installed hash authorizes repair from the shipped YAML template with project values applied by the same editor; dry-run lists `repair config (written by previous upgrade)`. A hash mismatch refuses with exit 3 and a manual restoration instruction, preserving the file. Init on an existing project with a differing `--writer`, `--reviewer` or `--agent` exits 3 before any write and prints the `agents.<role>.command` line to change by hand. Force reuse preserves the existing lock, or leaves an unknown legacy installation without one. Without a legacy lock, original defaults are unknown: existing keys are preserved, missing keys receive current defaults, and differing kit files are listed.

All path collisions use one shared NFC + lowercase key. A differently spelled existing project path is kept and reported, including aliases through directories; a skipped shipped file prevents a current attestation. Unknown or edited obsolete files are kept. Deletion requires matching installed bytes and a complete, internally consistent installation inventory; incomplete or edited locks cannot authorize removal. Doctor reports current only when every file the invoking kit ships is present with its expected hash and is listed in the lock, as well as all recorded installed hashes matching. Invalid locks are unknown; inconsistent inventories or changed files are drift. The checksum detects inventory edits; it is not an authenticated signature against an owner who rewrites the whole record.

Upgrade acquires `.kit-upgrade.lock` by exclusive atomic creation before planning and holds it through staging, renames, cleanup or rollback. Any existing lock refuses with exit 3, naming the holder PID, process start time and whether it looks live or exited, without changing the lock: confirm that process has exited, then delete `<project>/.kit-upgrade.lock` and rerun. Dry-run and a no-op also use a transient lock but leave the tree unchanged. An older source version, or a source commit proven to precede the recorded commit, is refused with exit 3 explaining recorded/source versions and commits; no downgrade override is provided. Commit ancestry is checked when both commits resolve in the source repository. Replacement bytes are staged and rolled back from preserved originals on errors; stale plans are rejected before mutation. This provides error rollback and writer exclusion; power-loss recovery and concurrent-reader isolation remain unverified.

Fresh automated intake runs stage lint before records exist, then a fresh reviewer and the human gate (`GATE: PENDING`, exit 2). Definition revisions bind only kind, sorted ids and definition id/version. Writer content changes produce new content-addressed candidates and receipts without rebinding; added, removed or renamed scope ids stop at `scope-version-required`. Content changes after approval still stale the gate. Dynamic product output ids are declared as strict patterns derived from shipped prompt placeholders; adding or removing a concrete file remains a membership change.

Each gate hashes its own stage definition and applicable scoped bindings, shared runner settings, and the versions used by its inputs. Template and ruleset dependencies include definition inputs and the enabled review rubric; workflow is shared, and skill version applies where a stage declares a skill. Registry loading and receipt freshness use the same dependency selection. Bumping another stage's gate version leaves earlier gates current; changing a used shared input still invalidates consumers, with the existing conservative downstream fallback when impact proof is incomplete.

Wrappers live in `tools/agents/{codex,claude}-{writer,reviewer}` and `tools/agents/grok-reviewer`. They consume stdin and emit only the final response on stdout, fail nonzero on CLI failure, and never forward provider diagnostic text that could contain credentials. Reviewer invocation is a new process with no resumed writer session; Codex uses an ephemeral read-only session, and Claude disables tools and session persistence. Grok uses a read-only sandbox, plan permission mode, only the read-only file tools read_file, grep and list_dir (grok CLI shortens large prompts and the model reads the rest from its session file; reads are not confined to the review snapshot), no shell/write/web/subagents/MCP, and lean environment settings that disable shared Claude/Cursor rules, skills, agents, hooks, MCP and memory. Its temporary prompt file is removed after the process exits. Only JSON with `stopReason: end_turn` and nonempty final text succeeds; cancelled, incomplete, malformed or empty answers fail without emitting a review. The runner additionally gives reviewers a fresh input copy. Built-in commands use project-relative wrapper paths; definitions include the wrapper files so they are present in that copy.

Wrapper parameters: `--model <id>`, `--effort low|medium|high|xhigh`, `--cli <executable>`, `--timeout-ms <positive-ms>` (default 1500000), `--dry-run` (argv only, no prompt/CLI call), `--help`, and `--metrics <JSONL-log>` (exit, wall time, output byte count/digest; Grok also includes available numeric token counts). Codex model/effort inherit its CLI config; Claude reviewer defaults to `sonnet`, writer inherits CLI config; Grok reviewer defaults to `grok-4.7`; effort inherits config unless provided. Use the runner default for long generations; a smaller explicit `--timeout-ms` is accepted and can stop the call before the wrapper deadline (exit 4). The runner spawns each agent command as one process-group leader; the shipped wrapper keeps its provider CLI in that group. Runner timeout, overflow, SIGINT and SIGTERM terminate the group with SIGTERM, 250 ms grace, then SIGKILL, including ordinary grandchildren reparented after an intermediate exits. The wrapper also terminates its CLI on its own timeout/interrupt; when invoked standalone it avoids killing the caller's shared group. The `ps` ancestry scan is best-effort extra coverage, not an ownership guarantee. A provider that deliberately creates its own session/group (`setsid` or detached spawning) can escape user-space group cleanup on macOS, especially after rapid reparenting; complete cleanup is not guaranteed for that case.

```sh
node tools/agents/codex-writer --model <model-id> --effort high < prompt.txt
node tools/agents/claude-reviewer --dry-run
```

Doctor reports PASS / NOT RUN / FAIL for Node >=18, Ajv Draft 2020-12, configured agent CLI availability (never invokes an agent), and optional Playwright/Chromium for reader verification. Point `SPEC_AJV_MODULE` to an installed `ajv/dist/2020`, or make that module resolvable from the project. Use `PLAYWRIGHT_FROM` for a directory containing `node_modules/playwright`; doctor probes an actual Chromium launch (5000ms timeout) and closes it. Missing or unlaunchable headless browsers stay NOT RUN with the install command. Doctor exit 0 means required checks passed, 1 means a required check failed, 2 means a selected project/options could not be checked; unavailable browser capabilities do not fail readiness.

The project supplies `config/pipeline.yaml`, exact-version gate definitions, a dependency graph, prompts and the deterministic commands named by its config. The runner validates them; it does not manufacture missing registries, write kit prompts, lint documents itself or infer missing AC coverage. Configuration paths are project-relative. YAML maps/sequences, flow collections, scalar quotes and block commands are supported; aliases, tags and duplicate keys are rejected.

Use an actual final build revision for UIUX. `not-built` supports pre-code review and keeps G4 pending. Head comes from Git when the project is inside a worktree; otherwise provide `--head`. Handoff and imports require the explicit `gates.baseline` registry. Exit codes: `0` settled, `2` awaiting authority/repair/cap, `3` bad input, `4` unavailable or failed tool execution. A failed writer or reviewer command keeps its stderr, with secrets removed by the shared `redact()` (URL userinfo, `Authorization` values, bearer/basic tokens, `sk-`/`gh*_`/`github_pat_` keys, `name: value` / `name=value` / JSON `"name": "value"` secrets including quoted values with spaces, multi-line quoted values, YAML block scalars (`|`, `|2`, `>-`, optional trailing comment, LF or CRLF, across blank lines, until the indentation decreases; capped at 256 KB after the indicator) and PEM private keys; it also scrubs stored eval and writer/reviewer stdout logs), in `review/log/<stage>-writer-<fix>-<review>-stderr.txt`, `<stage>-review-<round>-stderr.txt` or the `-format-repair-stderr.txt` twin; the exit-4 message shows only the first redacted line and names the log. Shipped wrappers still drop the provider's own stderr ([known limits](../../docs/known-limits.md)).

Agent timeouts share `agent-timeouts.mjs`: wrapper default 1500000 ms, runner default 1800000 ms. The 300000 ms margin lets wrapper cleanup finish before the runner deadline; init adds no timeout override. `--timeout-ms` explicitly overrides the runner deadline, including values below the wrapper default; no clamping occurs. A shorter runner deadline terminates the call and exits 4. Runner commands own a process group; timeout, output overflow and interrupt send SIGTERM to the tracked tree (including detached descendants), wait 250 ms, then SIGKILL survivors.

Agents receive stdin and return stdout. Commands are parsed into argv without a shell; configure a local script when shell operations are necessary. A single literal output uses plain text. A single pattern or several declarations require exactly one fenced `files` JSON map: every literal is required, pattern matches are optional, the map must be non-empty, and no other path is accepted. Malformed output writes no partial files and consumes a fix round.

Writer instructions compose `prompts/_common.md` and the stage prompt. Reviewer instructions use the common rules before the writer-only result-format section, followed by `prompts/reviewer.md`; writer output formatting does not apply to reviewers. Init ships the entire prompts directory. `composedPromptFiles` is the shared instruction-file inventory for stage inputs, the receipt's reviewer prompt pin and receipt freshness: changing either common rules or reviewer instructions invalidates current reviewed evidence, while unrelated file changes do not.

Evaluator output must contain a visible observation on stdout or stderr, as classified by `output-observation.mjs`. Terminal escape payloads, control characters, Unicode whitespace, BOM and zero-width characters alone are unavailable observations (runner exit 4), even when the actual command exit is 0. Raw output and its real exit stay in the command log; missing observations consume no behavioral repair round and cannot create a receipt. Writer, manual-result and reviewer checks share this classifier; the existing `files` and `review-data` formats must also parse. Eval config remains `run`/`per_file`, with no machine-readable evaluator format declaration.

Reviewer stdout begins with `VERDICT: PASS|NEEDS_CHANGES|FAIL|BLOCKED|NOT_RUN`, then exactly one fenced `review-data` JSON block:

````markdown
VERDICT: PASS
```review-data
{"criteria":[{"id":"source","mandatory":true,"score":2,"evidence":"Original AC compared with final outcome"}],"findings":[]}
```
````

Criteria and findings follow `format/schema/gate-review.schema.json`. Applicable mandatory criteria require score 2; open Critical/Major findings block. Accepted Minor findings require a registered PO email, reason and follow-up through the human gate. Agent-supplied accepted-minor is treated as open; only the PO edits that disposition and accepted_by. At the review cap or a no-edit repair, an independent NEEDS_CHANGES review with only open Minor findings and all applicable mandatory scores 2 writes GATE: PENDING listing each finding and its PO decision. Approval remains ineligible until each finding is accepted with reason/follow-up or the PO requests changes. The saved review binds the exact original-source snapshot, current source/context, composed prompt files (including `_common.md` and reviewer instructions), rubric, and reviewed outputs. Cap/no-edit settlement requires this complete binding to match; drift invalidates the review result. At an exhausted cap, source/context drift stops with "source/context changed after last review", without minting a current receipt, granting another review call, or resetting counters. Other cap stops remain unchanged; counters never reset. All-NA is NOT_RUN. Reviewers receive original source snapshots, the rubric, final outputs and current runner-observed eval evidence in a fresh temporary project copy. Each current eval includes command, exit, declared error/warning counts (null when absent), bounded log excerpt, digest and `truncated` (true only when selected content was cut for the byte budget); full logs are copied too. Historical evals from before the last output are excluded. A writer repair request after failing evals carries the same bounded excerpts (reusing this evidence), so a writer that cannot open files still sees the lint errors; the request text is not hashed. Mutation of that copy fails the run. This is filesystem copy isolation, not a kernel sandbox: use a trusted read-only CLI command that cannot access absolute paths outside its copy.

A visible answer with a malformed review format gets one fresh reviewer process with the same sources, final outputs and the exact parser error. This format repair consumes neither a writer fix round nor another review round. The initial answer remains in `review/log/<stage>-review-<round>.txt`; the repair answer is saved separately as `review/log/<stage>-review-<round>-format-repair.txt`, and the re-ask is recorded in the audit. A second malformed answer or failed repair process exits 4 with the parser error and saved raw-output path. No visible reviewer output exits 4 immediately without a re-ask. Manual malformed answers print the error and raw path, then wait at a refreshed manual checkpoint (exit 2); submit a corrected answer with `--result`.

For either agent set its configured command to `manual`. The runner prints the prompt and exits 2 at a persisted checkpoint. Save the response inside the project and resume:

```sh
node tools/run/run.mjs --project /path/to/project --build not-built --result response.txt
```

`--paste response.txt` supplies the first manual writer result without a prior checkpoint. A result is consumed once and never reused for the reviewer. Manual reviewer responses remain non-independent unless the human explicitly supplies `--independent-review` after a fresh chat. Changed inputs or mismatched checkpoints reject the pasted result.

Default traversal uses the eleven configured stages. `--stage <name>` selects a legal entry point and continues forward through enabled stages. Existing-stage re-entry requires `--transition <file>` and recorded exact-scope authority. Requirement/expected-result changes require PO authority. On CHANGES_REQUESTED re-entry the retained human request takes precedence over earlier automatic repair context; persisted caps still apply. A reopened gate (CHANGES_REQUESTED or stale) forces repair once per distinct cause: the runner stores a `repair_entry` key in `review/runtime/<stage>.json` when a repair actually starts. The stored entry is `{key, foreign}`: `key` hashes the gate's inputs, outputs, receipts and last change request, the effective config hash and the live candidate pins (`--build`; head and base for handoff); `foreign` is a map `{path: sha256}` of the changed paths that were not this stage's own repair write, with the bytes they had when the repair started. Cause identity is content based: a later run is the same cause only when `key` matches and every currently changed path is either this stage's own repair write (current bytes equal the hashes its writer recorded in `written_outputs`) or still has the exact recorded bytes. A new path, different bytes at a recorded path (a second hand edit), or a former own write whose bytes moved on is a new cause: it appends a new invalidation audit event and re-enters repair. A `--supersedes` re-observation skips repair and does not store the key. While that gate stays invalidated, repeated invocations over the same stale set write one invalidation audit event, not one per call. A declared output counts as the stage's own repair effect only while its bytes equal the hashes recorded from this stage's writer (`written_outputs` in the runtime state); any other write to it is audited as a new invalidation and marks the affected scoped projections STALE. Persisted caps survive restarts and deleted runtime projections; additional rounds require an active exact-scope PO continuation and append-only audit evidence.

Repair and reviewer attempts reserve their counters before execution, under a stage runtime lock, then atomically replace the runtime projection. Manual prompts consume a round when their response is submitted. A held lock or stale reservation rejects without execution. If an interrupted process leaves a lock, verify its recorded PID has exited before removing that stage's lock; a projection that disagrees with audit remains rejected and must be reconciled against the audit before retry.

Gate first lines and their model human state agree. Existing pending decisions remain pending when a role is toggled. A raw command PASS is separate from independent review, human approval, receipt freshness and delivery. Gate context inventories use raw-byte SHA-256. A complete reviewed dependency census allows scoped invalidation; unproved mappings use the conservative downstream fallback. One candidate manifest covers every aggregate/scoped member in a stage run. Scoped decisions bind to member revisions and artifact hashes; a changed aggregate digest reopens handoff.

Current evidence follows [gate model §5](../../format/gate-model.md#5-evidence-receipts-coverage-and-independence). Freshness overlays apply first; timestamps, ids and file order never select a winner. Every unretired head must pass the required evaluation and review. Contradictory observations are preserved and keep the gate pending with `conflicting current evidence <ids>`. Disabled review stays explicitly disabled; `NOT_REQUIRED` skips only human waiting and never establishes reviewed quality or replaces evaluation, review, freshness, progress or delivery evidence.

Explicit evaluator/rules pins must match the receipt's review versions; mismatches reject as `Q-RECEIPT`. Absent pins use those review versions in the evidence key. Eligible reviews inherit the registered-PO accepted-Minor policy. A freshness overlay can retire a migrated FAIL, including one without a candidate manifest.

Before evidence counts, its whole `scope.revision` must match current target membership. Impact census, gate invalidation, decision import, publication and propagation share this check. Changed bytes retire a multi-member receipt before revision validation. Graph-completeness evidence requires a correctly bound artifact or bundle receipt; a legacy graph-only payload cannot establish a reviewed census.

Scoped reuse requires a source-derived dependency census in addition to the graph's `complete` flag and current change closure. It follows every declared ancestor/relation: all `trace.*` fields, US/contract AC ownership, amendments and decisions, scenario ownership, screens, boards and ui-contract links. Missing nodes, required edges, incorrect node kinds or unresolved declarations make the no-impact proof unavailable; invalidation uses the conservative fallback.

An independent re-observation may explicitly retire receipts on identical member keys and source bytes:

```sh
node tools/run/run.mjs --project /path/to/project --build not-built --stage prd --supersedes receipt-id --reason "Independent re-observation on identical bytes"
```

Repeat the `--supersedes <id> --reason <text>` pair for multiple heads. Retirement runs evaluation and a fresh review of the existing bytes; it does not launch the builder or repair artifacts. Existing-stage re-entry still requires its authorized `--transition`. Manual review uses its persisted checkpoint and `--result ... --independent-review`; retirement never bypasses caps or invents independence. Domain/key/source mismatch, missing targets, missing reasons and self grading reject before receipt/audit writes. An `eval` audit event witnesses each new/retired id pair. Retirement is not transitive: a superseded or stale receipt's own retirement links are inert.

Human stage gate decision (run personally by the PO):

```sh
node tools/run/decide.mjs --project /path/to/project --stage prd --as <your-po-email> --approve
node tools/run/decide.mjs --project /path/to/project --stage prd --as <your-po-email> --approve --accept-minor F-01 --reason "Presentation only" --follow-up "Cleanup next release"
node tools/run/decide.mjs --project /path/to/project --stage prd --as <your-po-email> --request-changes "F-01: align presentation with the confirmed source"
node tools/run/decide.mjs --project /path/to/project --stage prd --as <your-po-email> --continue --reason "Repair the last review findings"
node tools/run/run.mjs --project /path/to/project --head fresh-source --build not-built
```

Replace `<your-po-email>` with your registered PO email; it is a placeholder, not literal shell input. An automated agent may run decide only through `/spec:gate` after the PO explicitly chooses in the host ask-user tool in the same session, using `--confirmed-via ask-user`; outside that path it must **never run decide.mjs** or supply `--as`. Identity is asserted-local, not cryptographically authenticated. `--help` shows the forms; `--config <path>` selects a non-default project config. The runner prints both decision forms at every PENDING stop, filling in every open Minor id; repeat `--accept-minor <id> --reason "..." --follow-up "..."` for each finding.

Approval and changes requests require an enabled, current PENDING gate, a configured `roles.po.approvers` actor, passing evaluation and current eligible independent review. They reuse the runner's input/output/config, receipt and review-binding checks. Critical/Major findings block these decisions; approval additionally requires a reason and follow-up for every open Minor. Missing/duplicate/unknown findings, stale evidence, ineligible review, unregistered actors and non-PENDING gates refuse with exit 3 and no writes.

At a review or fix cap, read the last review log and run the printed `--continue --reason "<text>"` command personally as the PO, or stop the stage. This form requires `--project`, an enabled stage at its effective runtime cap and a registered PO; it needs no gate and excludes approval, changes requests and Minor acceptance. It writes a schema-valid exact-scope continuation (one extra round, active for 30 days), an immutable PO decision and its audit witness, or refuses with exit 3 and no writes. The runner discovers authorized exception ids from definitions and exact-scope recorded PO decisions, deduplicates grants and retains counters. Review-cap re-entry repairs the last findings, evaluates and runs one fresh independent review; fix-cap re-entry repairs and evaluates once. Major findings still stop without a gate; Minor-only findings follow the existing PENDING/acceptance contract. Never delete `review/`. Older projections without source/build pins need one runner invocation with the original `--head`/`--build` to record them before `--continue`; pins are never guessed. Ordinary write errors restore prior record bytes; power-loss recovery and simultaneous PO commands are not isolated transactions.

Approval writes consistent APPROVED gate/model states, the approval `{by, at}`, accepted-Minor dispositions with `accepted_by`, scoped projections, an immutable local decision and the same hash-chained audit witness used by batch import. The reviewer receipt remains unchanged. A change request writes CHANGES_REQUESTED and retains `CHANGE REQUEST: <text>` plus actor/time; the next runner invocation re-enters repair using that PO text. Existing repair/review caps still apply and can require a scoped PO continuation. The command prints the written paths, decision, audit, dispositions/request and next runner command. Use a real build revision in that next command when proceeding into UIUX or handoff; `not-built` is for pre-code stages.

A stage decision binds its stage scope and current candidate and records gate/receipt references; it does not create a batch packet or publication authority. Batch import retains its packet/Change Set bindings and publication contract below. Both entrypoints use the same immutable-record writer and audit envelope (decision id, actor, scope, canonical record digest, refs, asserted-local authority and dirty flag).

Human decision import:

```sh
node tools/run/run.mjs --project /path/to/project --build final-build-rev --import-decision decision.json --packet-data packet-data.json --as po@example.test
```

An automated agent must not supply `--as`. This is an asserted local identity in `roles.po.approvers`, not cryptographic authentication. Imports validate canonical data, current pins, complete membership, deterministic overrides, current independent evidence and semantic propagation before approval writes. Requested/deferred members remain pending. Identical decision retries return the original audit event; conflicting reuse rejects.

Import rebuilds the entire canonical packet with the reader's existing builder, configured `project.spec_root` and current project registries. In a Git project it reads spec bytes from the live HEAD without checking out files; an unavailable or unbound source fails closed. Changing a displayed field and recomputing the submitted digest cannot establish approval. Registry changes require a regenerated packet. For projects outside Git, the existing explicit `--head` mode uses the configured local spec snapshot. Unrelated dirty files remain recorded in the audit; repinned uncommitted spec bytes cannot replace HEAD, and the existing dirty-tree handoff restriction still applies.

Import recomputes heads from the project receipt store plus packet evidence. Embedded receipts can block approval but cannot retire store receipts. Validated packets are retained immutably at `review/packets/<data-sha256>.json` so publication, including an idempotent retry, recomputes the approved packet's evidence against the current store and overlays.

The local `recordDeliveryEvent` API in `delivery-state.mjs` keeps publication, receiver acknowledgment and receiver switch separate. Its caller supplies freshly verified current pins; publishing produces immutable local baseline files and grants no deployment authority. Required corpus commands remain the project's configured evals and rerun with changed bundles.

Publication requires the immutable saved batch decision to match its audit digest, approved scope/revision, candidate pins and Change Set binding. Historical approvals without that binding fail closed; a new human import with a new decision ID is required. Exception imports and prototype-first transitions require the same exact scope and authorizing PO; receiver switches require an acknowledgment for the same Change Set, scope and candidate.

Runtime evidence lives under `review/`: gates/scoped projections, immutable candidate/receipt files, hash-chained audit, persistent runtime/manual checkpoints, original-source snapshots and command/review logs. Gate-model export/rebasing into a spec bundle is follow-up work authorized separately by controller reply R12; this runner operates the live project-root registries.

## Agent commands and PO source

`status.mjs --project <dir> [--json]` reads enabled stages in canonical order, exact gate/freshness, counters/effective caps, continuation eligibility, open question records minus `input/answers.md`, and the next command. It writes no lock or runtime state.

`decide.mjs --confirmed-via ask-user` records `channel: agent-ask-user` in the immutable decision and audit witness; without it the channel is `direct`, as for legacy records with no channel. Only `/spec:gate` may use the agent path, after the PO explicitly answers the host ask-user tool in that session. This is an asserted local channel, not authentication; all freshness, authority and quality refusals still apply. Chat-only fallback leaves the decision to the PO personally.

Init/upgrade add an empty `input/answers.md` PO source. Clarify and later stages already reading decisions include it; intake excludes it. Upgrade preserves existing answers and G1 approvals; answer-context changes intentionally stale downstream gates. The clarify writer copies only supplied rows into the ledger and records with exact answer, actor, UTC date and source reference.
