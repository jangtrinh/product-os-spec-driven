# Design and UIUX model

Normative companion to [Format v2](SPEC-FORMAT-v2.md) and [gate model](gate-model.md). Core is model-, DS- and tool-agnostic. Design declarations, behavioral selectors, source locators and verified evidence are separate records.

## 1. Adapter boundary, authority and token ownership

Manifest `design.profile` points to local JSON conforming to [design-profile.schema.json](schema/design-profile.schema.json). A profile requires `id`, `version`, `authority`, `tokens`, `catalogs`, `capabilities`, `rubrics`, `evidence_providers`, `locales`, `viewports`, `modes`, `inputs`. Profile paths are spec-relative exported copies; runner config can name project-relative original inputs, whose digests MUST match exported copies. Core never assumes a broker, Figma plugin, DESIGN:OS CLI, palette, canvas grammar, model, or provider is installed. Reader theme is independent of the feature DS.

`authority` is an ordered nonempty list `{id,path,revision,kind,non_waivable}`, kind `identity|principle|ruling|contract|ds|copy|default`. Read project identity → ratified principles/current scoped rulings → product/feature contract → declared DS/copy/pattern authority → generic defaults. Exact/newer scoped rulings supersede older guidance on that subject, not unrelated global rules; floors remain non-waivable. Capture each ruling's source quotation, scope, date, superseded id and application in the decision ledger. Unresolved contradictory authorities are OPEN[blocking] for dependent scope; never choose the first cache silently. Project adapters declare case-specific order/departures with owner reason.

`tokens` = `{owner, source, revision, generated, sync_direction}`; owner email/role, generated sorted unique local paths, sync_direction nonempty policy. Only the declared source owns edits; mirrors MUST remain generated and provenance stamped. Authority changes need an approved decision, impact closure and consumer rechecks. A project design-system adapter selects code-owned `design/tokens.json`, code edit → ds-sync generated CSS/docs/cache → Figma variables alignment. Figma drift never silently flows upstream. DESIGN:OS sealed stores/registries are portable adapter caches with explicit provenance, not automatically project design-system authority. Core checks relations/provenance and prohibits source=mirror; adapter executes DS-specific token/parity checks.

`catalogs` entries `{id,path,revision,kind,locale?}` (`component|pattern|copy`) define stable adapter-qualified handles and API/usage references. Authority entries of kind `ruling` point at a [rulings-index](schema/rulings-index.schema.json) payload (AM-6: id, subject, scope, date, status, supersedes, non_waivable, text_ref). Component and pattern catalog payloads conform to [ds-catalog.schema.json](schema/ds-catalog.schema.json) (AM-4): `{version:"1", adapter, kind, revision?, items:[{handle, name, api_ref?, usage_ref?, status: active|deprecated|retired, replaced_by?, reason?}]}`; handles are unique within a catalog; a reference to a `retired` handle is an error, to a `deprecated` handle a counted warning that names `replaced_by`. Copy catalogs require locale, project/spec-local path and exact revision; their payload is `{locale,entries}` per [copy-catalog schema](schema/copy-catalog.schema.json). Locale must match the profile declaration and catalog; glossary source keys resolve exactly in entries. Component/pattern catalogs omit locale. A display/component name is not a guaranteed stable key. Reuse ladder: existing component → existing pattern composition → extension approved by shared owner → new component with reason. Shared-master changes need affected-consumer inventory, alternatives, owner and decision before mutation; per-screen forks cannot evade ownership. Record departures with measurement/expected/actual/affected consumers/owner/resolution and CURRENT evidence. Optional DESIGN:OS/Figma-agent/project design-system adapters are selected in pipeline `design_adapter` profile path, not hardcoded into core.

Capabilities list `{id,status,reason}`, status `available|missing|unverified`. Evidence providers use id/version/capability and name optional IA/flow lint, criteria-evidence coverage and approved visual-baseline services. Core stores portable receipts; pixel similarity is not usability or AC acceptance. Critic modes Operate/Read/Persuade/Experience are optional adapter choices; a project design-system adapter may mandate Operate and current scoped rulings as referenced authority, not global app taste.

## 2. Identity namespaces and screen/state inventory

| Namespace | Identity and join |
|---|---|
| screen | retained `S01`, `S01-b` pattern; suffix is part of screen id, not an external locator |
| state | `<screen>/<state>`; state kebab-case (normal, empty, loading, error, disabled, focus, long-content, no-permission, project-specific) |
| board | `W-01`, same basename HTML↔PNG under wireframes; distinct from screen |
| component/pattern | `<adapter-id>/<handle>`; resolves in versioned catalog; no global name identity |
| scenario / AC | `<US>.SCN-n-n` / `<US>.AC-n`; contract ACs qualified by contract document id |
| external source | symbolic `source-<kebab>` resolved only by generated source map; never a screen/node id alias |
| receipt | evidence id scoped to build/screen/state/SCN; freshness independent of work progress |

New `type: screen-inventory`, tier ux, lives in declared UX folder. Required front matter `data: <spec-relative-json>` points to [screen-inventory.schema.json](schema/screen-inventory.schema.json); body headings `## Screens and states`, `## Flow and disclosure`, `## Gaps and departures` provide readable explanation and links. JSON owns structured rows; no separately edited duplicate table. Legacy `type: ux, inventory: true` remains readable; strict new design output requires explicit structured coverage or a source-backed conversion.

Payload `{version, screens}` rows require `screen`, `state`, `route`, `roles`, `scope`, `us`, `ac`, `scenarios`, `flow`, `boards`, `components`, `patterns`, `data`, `source`, `availability`, `overlay`, `consequences`, `evidence`. `route` is declared path; roles/scope nonempty availability identifiers; US/qualified AC/qualified SCN joins resolve. Flow/data are source references or `not-applicable: <reason>`; arrays may be empty only with explicit gap recorded in body and dependent gate blocked if required. `availability` describes conditions; overlay `none|modal|non-modal`; consequences declare observable action/effect text; evidence contains receipt ids, initially empty.

Screen/state key is unique; same route may host several screens/states. Every UI AC/scenario maps to applicable inventory states or explicit unresolved coverage; a no-UI US declares front matter `no_ui` with reason and PO applicability confirmation at gate. New design must consider normal/empty/loading/error/disabled/focus/long-content/no-permission and overlays, mark applicable rows or list state-specific NA reason/confirmer; no manufactured states. Progressive disclosure/findability and IA remain linked UX authority in Flow and disclosure, never reduced to selectors. Empty state/role coverage blocks dependent G4.

## 3. Explicit source and generated locator sidecar

Every row's `source` is `{kind: figma|html-board|not-created, ref: <symbolic id or null>, reason?: text}`. Figma requires symbolic ref. HTML-board requires a W-id ref to a local board. Not-created requires reason and ref null; authored boards can still appear in `boards`. D10 permits no Figma pointer and an authored HTML board; it never permits an omitted source field or fake Figma node. `not-created` represents absent external source, not absent implementation. A board can be approved design without proving coded behavior.

Manifest `design.sources` optionally names a generated [design-sources.schema.json](schema/design-sources.schema.json): `{generated: true, generator, version, at, inputs, entries}`. `inputs` is exact local source-path→SHA-256 map; each entry `{id, tool, locator, revision, snapshot, at, authority, freshness, status}`. `locator` is adapter data `{url?,file_key?,node_id?}` (at least URL or file key); Figma node id required by its adapter for frame resolution. `snapshot` local asset or null, freshness `CURRENT|STALE|MISSING`, status `active|retired|unverified|missing`. Unverified/missing entries cannot claim CURRENT. Retired sources remain disclosed, never used as fresh acceptance. Core never fetches remote locators; display local snapshot + offline-generated link/provenance.

Resolvable Figma URL/file key/node id and generated canvas population counts MUST NOT occur in curated prose/front matter/registry. Curated records use symbolic refs and design intent/composition/deprecation rationale. Frozen original input citations remain immutable evidence (not a current locator inventory); migration preserves them in cited source artifacts/history and generates a sidecar for live navigation. Numeric requirements, dimensions, stable screen/board ids and business data remain allowed. Lint examines artifact kind and structured locator/count claims, not a blanket number regex. Generated sidecars/counts carry generator/input/time/revision; curator never hand-edits them.

## 4. Behavioral ui-contract extension

Keep the old row's `screen, route, us, element, kind, used_by`. New design output requires all additional fields `state, roles, scope, components, patterns, target`. Normalized row follows [ui-contract.schema.json](schema/ui-contract.schema.json). New table header `Screen | State | Route | Roles | Scope | US | Element | Kind | Components | Patterns | Target | SCN`; arrays comma-separated, `—` means empty components/patterns/used_by, never empty roles/scope/target. Six-column old tables remain valid for unenabled/legacy workflows; design-enabled checkpoints reject absent extension (without changing legacy-absent migration debt). No extended row may be partially specified.

`target` describes observable behavior, with source AC and consequences in inventory; component/pattern refs describe reusable implementation, never a lookalike inferred by name. Selector is accessible role+exact name OR stable test id, mutually exclusive. Expand roles × scope into individual availability contexts for uniqueness. Uniqueness is within screen/state/role/scope; repeated same selector in same context shares union US/SCN. A selector repeated in disjoint states/roles is legal. Routes/roles/scope agree with inventory. Every listed US declares screen; SCN associations resolve against listed US and actual state mapping; every UI auto SCN has a relevant row. Every applicable inventory screen/state has ≥1 row, including a declared non-interactive output target for states without controls. A genuinely no-UI story uses its explicit no_ui reason rather than inventing an element.

Contract precedes UI code and guides TDD. Figma layer names/low-fi DOM selectors never become coded selectors automatically. Missing selectors remain explicit legacy debt or blocking new-design gap; lint cannot invent them. Image captions and source refs cannot substitute for behavioral targets. Migration must report each missing selector and new relation.

## 5. Images, visual evidence and capability limits

Retain Format §7 coded versus wireframe: coded assets have exact build/state provenance, wireframes require not-built reason when used in a coded page; matching HTML↔PNG board association is checked. Denied/missing/retired assets remain visible as such and never silently substituted. Generated role views and boards do not prove implementation. Caption names source role, revision, state, viewport/mode, locale and freshness.

Visual receipts use gate-model evidence schema with `visual` requested context `{screen,state,role,scope,scenarios,width,height,mode,locale,fixture}`. Each receipt covers exactly one role and one availability scope, both resolving in that screen/state inventory row. Expand the declared roles × scope, SCN and viewport/mode/locale/fixture combinations into explicit cells; if not every cross-product context applies, enumerate the allowed tuples and source-backed exclusions in the planned matrix. Cell identity is canonical JSON of `[screen,state,role,scope,scenario,width,height,mode,locale,fixture]`, one identity per qualified SCN in the receipt. Match every identity field exactly; opaque fixture names never imply a role. A receipt may supply several listed SCN cells only after each association is checked. Admin/workspace and viewer/project captures are distinct even when other fields match; wrong-role/scope reuse is V-MATRIX RED. A copied capture path cannot prove a second context without its own actual context-bound observation and digest/probe provenance.

Executed visual observations (integer exit, PASS/FAIL) additionally require nonnull `{browser,build,ds,probe,png,measurements}`. For unexecuted NOT_RUN/BLOCKED/SKIPPED/NA (exit null), keep the complete requested cell context, `freshness: MISSING`, `selected: 0`, no passed AC, real diagnostic-log artifact/hash and recovery action. Capture outputs are omitted or null; no invented browser/PNG/measurement paths. SKIPPED/NA additionally records the cell identity, reason and authority confirmer in coverage.na; unavailable capability is NOT_RUN/BLOCKED, not NA. An unexecuted receipt cannot be CURRENT or count toward a passed numerator. Executed receipts still require actual capture metadata and paths; absent outputs are Q-RECEIPT/V-MATRIX RED. PNG and measurement files local and digest-bound in artifacts; receipt timestamp actual capture. Matrix floor widths 375/768/1440, heights explicitly declared, light/dark default. Adapter/brief adds viewports and breakpoint ±1; a project design-system adapter may add 874×827. Floor widths cannot be removed silently, any non-applicable state/mode requires explicit authority exception and remains visible. Required states/roles/scope/scenarios are enumerated in matrix, no count-only coverage. Responsive reader A5.3 keeps all four widths in both modes.

For each applicable matrix cell require final-revision screenshot, structural/layout probe, keyboard/focus/label/a11y check, interaction/AC evidence and actual independent visual inspection. These are separate checks/receipts, even if one capture supplies their inputs. Layout probes record geometry/spacing/overflow; images from previous build cannot close current G4. Browser/font/plugin/DS-map/mode absence yields named NOT_RUN/BLOCKED, recovery action and missing cell; allowed SKIPPED/NA requires reason/confirmer and contributes zero passed numerator. Never substitute an unauthorized bridge/provider or invented artifact for unavailable capability. A scout/report can complete while feature acceptance remains pending.

## 6. UIUX rubric, input contracts and copy

Core mandatory rubric scores 0/1/2, every applicable criterion 2: task completion against original AC; full applicable screen/state/role coverage; IA/findability/disclosure; action consequences/error recovery; DS/token/component/pattern compliance; responsive geometry/no overflow; keyboard/focus/labels/contrast; locale/copy/glossary clarity; source/evidence provenance and freshness. Criterion records follow model-common: optional applicability defaults to applicable for historical rows and requires integer score 0/1/2; explicit applicability na requires score null, reason and authority confirmer. Criteria can be NA only with reason/confirmer, remain visible and contribute zero passed numerator. Compute VERDICT only from applicable scores (any 0 FAIL; else any 1 or open/accepted-minor finding NEEDS_CHANGES; else nonempty all-2 PASS). Enabled review verdicts are PASS|NEEDS_CHANGES|FAIL|BLOCKED|NOT_RUN. No applicable criteria yields NOT_RUN, persisted unchanged in gate-data.review.verdict and the scoped model review state; NOT_RUN is never eligible/passing. Disabled review retains false/false/null and empty criteria/findings per [gate-review schema](schema/gate-review.schema.json). Fixed/rejected findings remain history. Every applicable mandatory score stays 2 for eligibility. Critical/Major block; accepted Minor needs PO reason/follow-up. Adapter rubric adds mandatory criteria, never reduces core floors; a project design-system adapter may add Operate/current rulings. Taste/visual baseline comparison supplements criteria and cannot average away failure.

Design inputs: original spec/contract/REQ/AC, prior decisions/rulings in declared read order, screen/source map, DS adapter/token/component/pattern catalogs, tech context, flow/data/disclosure authority, writing/glossary, core+adapter rubric. Outputs: design intent/flow/states, inventory, selector contract, DS reuse/gap/owner decisions, source declarations, planned matrix and unresolved contradictions. Adapter requiring direction approval before canvas mutation must name that approval gate; design-stage completion does not require Figma availability when a valid HTML/not-created source is declared. Required Figma parity remains a separate pending check.

UIUX inputs: same authority plus final candidate build, original AC, TDD test/RED results, current screenshots/probes/interaction/a11y receipts and reviewer versions. Output: read-only independent rubric/findings/departures and scoped gate records. `config/pipeline.yaml` context arrays and stage prompts MUST list the actual declared files identically, including digests of exported copies and rules/prompt versions. Stages remain design/UIUX off by default; enabling them invokes acceptance, not file existence. No minimum agent count; separation of builder/reviewer/human remains required.

Glossary entries optionally add locale, source_key, retained_terms, exceptions `{text,reason,source}` using the exact [extended table grammar](glossary-grammar.md), including JSON cells, Markdown escaping, defaults and source resolution. Locale-aware uniqueness includes locale + NFC/casefold term; a concept has one preferred spelling per locale. Ban lists scoped by locale, exceptions narrowly grounded in source/ruling, not blanket suppression. Preserve diacritics/NFC, placeholders, units and verbatim business data; rendered semantic review required. EN-only docs need no fabricated bilingual rows. A project Vietnamese adapter reads its `ux-writing-vi.md`/`vi-glossary.json` authority and copy catalogs; glossary source keys resolve in declared locale catalogs. Unknown localization stays OPEN, not an automatic translation decision.

## 7. Reader projections and migration

PO shows design intent, coded/wireframe preview, screen/state/source/approval/OPEN and batch review packet. Dev adds flow/data/states/role/scope, DS refs/reuse/departures and behavioral rows/source links. QA maps qualified AC → SCN → screen/state → method/test → exact receipt/freshness with missing coverage visible. All views navigate screen/board/component/evidence joins, current/missing/retired/unverified source labels and local snapshots; never fetch external data. Reader cannot conflate its own light/dark shell with feature mode or its screenshots with feature visual acceptance.

Reader acceptance includes independent rendered craft, keyboard/focus/labels/working controls, design/evidence navigation, zero dead local links/overflow at 375/768/1440/874×827 light/dark. Long content, no images, explicit not-created, missing source, retired source, stale evidence and denied images are mandatory adverse fixtures. Missing external source is a disclosed state (no fabricated link), while broken generated local navigation is a failure. Invalid spec --force rendering stays visibly invalid and cannot generate an eligible approval packet.

Migration preserves every real UX doc/asset/HTML/PNG, screen/board/scenario id, flow, role/state/copy metadata and source quotation. Convert only explicit relations; report each absent/defaulted state/role/scope/DS/source/selector/evidence field and unknown join. Every absent/defaulted/unverified design relation is listed individually in the required migration report and disclosed by the reader; it creates no extra lint warning class. Accepted proof warnings remain only unassigned-method and exactly one legacy-absent UI-contract warning. Source kind can default not-created only with `reason: migration source not declared`, disclosed as unverified, not authoritative design acceptance. Unknown state is a reported unresolved mapping, never assumed normal. Preserve legacy-absent warning/provenance, never borrow wireframe selectors. Generated caches/node inventories remain generated; move locator navigation to generated sidecar with exact provenance and retain original citation in immutable source evidence. No source file edited, no renamed/dropped asset unreported. P6 validates copied-source counts plus link/role/source distinctions and adverse cases; missing acceptance data remains visible debt.
